### 19:34 UTC: Security review, pass 8 (`security/pass8`)

- [Pass 8](../research/security-review-2026-11-05-pass8.md) read what merged after pass 7 (the SR-81 and SR-82 fixes, the argument type check) and took a fresh pass over the proxy request flow, token exchange, leases and checkpoints, the console listener and the SDKs. Five findings, SR-85 to SR-89: one Medium, three Low, one Info; no High.
- SR-85 (Medium, fixed): an upstream could answer a call with `202` and put the answer in the body of the next `POST` of the session (a `ping` or another call); clients route it by id, the proxy did not label it. A `POST` labeller now claims answers to calls awaited in its scope, and a `POST` that forwards a request while calls are awaited has its answer read.
- SR-86 (Low, fixed): the awaited-call map evicted the oldest entry of any run when full, so one run could push out everyone else's; it now evicts from the largest run. SR-88 (Info, fixed): a repeated form `scope` on `/token` was taken last-wins; it is refused.
- SR-87 (Low, open): a list answer to an earlier request in a later `POST` body is not filtered; the list filter is not an authorization boundary and the fix touches three files. SR-89 (Low, accepted): answers later than the ten-minute `AWAITED_RESULT_TTL` pass unlabelled, and the Python MCP SDK waits indefinitely by default; closing it needs a design decision.

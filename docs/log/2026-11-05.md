### 23:32 UTC: Approval notifier outbox (`feat/notifier-outbox`)

### 20:13 UTC (2026-11-12): release the single-writer fence before `serve` returns (`fix/fence-release-on-stop`)

On `main` at `8c306c4`. Since the fence (#234), `a_notice_queued_at_shutdown_is_delivered_after_a_restart` and `an_approval_that_expired_while_down_gets_its_notice_on_start_once` failed now and then with "another process holds ...audit.sqlite.lock".

- **Cause.** The fence is the last field of `AppState`, so it goes when the last `Arc<AppState>` does. The test helper stopped a server by dropping its `Spawned` (`JoinHandle::abort`, which only schedules the cancel) and then dropping its own `state`. Still holding the state at that point: the aborted `axum::serve` future's router and each connection task's copy of it (a connection task only starts its own shutdown once the serve future has been dropped). The notifier threads hold the lease store, not the state, and are joined. Measured with a `Weak` in the helper: 139 strong references after the abort, sometimes still 139 after the notifier shutdown returned, released one scheduler turn later. The restarted server took the fence in that gap. `serve` had the same gap: it aborted the checkpoint timer, lease maintenance and the console and metrics listeners (all holding the state) without awaiting them. A supervisor restarting the process never saw it, because the process exits, but an in-process restart could.
- **Fix.** New `attenuo_server::run(config, state, app, listener, shutdown)`: what `serve` does after binding. One stop signal for everything; the console and metrics listeners drain like the main one; the timers stop between ticks (never in the middle of a blocking call) and are awaited; after a clean drain it also waits until every copy of each router is dropped. `AppState::released()` resolves when the state is dropped. `serve` = build, bind, `run` with the signal, then wait up to `RELEASE_GRACE` (2 s) for `released` and log `single-writer fence released` (or warn that requests abandoned after the drain still hold it). `serve_until` now awaits the aborted server task after a drain timeout. Startup is unchanged: no wait or retry on the fence.
- **Tests.** `tests/common::Running` runs a server through `run` and stops it: signal, await `run`, drop the state, await `released`. `approval_notifier.rs` and `dpop.rs` use it; the `dpop` helper that tried the lock every 10 ms until it was free is gone. New `a_server_stopped_by_run_can_be_restarted_on_its_file_at_once` (and the same on a multi-threaded runtime): 20 rounds of start, a database read over a kept-alive connection, stop, and an immediate `build` on the same file, with `run` polled in the test's own task, so no scheduler turn comes between its return and the restart. With `run` changed back to the old abort-without-await for the main or the console listener, round 0 fails on the current-thread runtime. The router-copy wait is not caught by a failing test (the gap closes during the later awaits).
- **Loops.** `approval_notifier` binary, 40 runs on main: 14 failed, all on the fence. After: 100 runs, 0 on the fence, 1 failed with `["approval.expired", "approval.pending"]`: a separate, older flake. After a restart the watcher queues `approval.expired` at once, while the backlog's `approval.pending` is only read from the outbox when the queue runs empty, so the expired one can go first. The module docs allow this ("may go out between two batches"); the test asserts the other order. It was there before (seen twice on main while measuring) and is not changed here. `dpop` binary: 40 runs, 0 failed.
- **Checked by hand.** The server binary on a file database with console and metrics on, SIGTERM, start again, three times: each run logs `single-writer fence released` and the next one starts.
- **Verified:** fmt; clippy (`-D warnings`, also with `--all-features`); rustdoc with `-D warnings`; `cargo test --workspace --no-fail-fast`: 1360 passed, 0 failed, 7 ignored; `cargo deny check`; links and hygiene; `cargo bench --no-run -p attenuo-server`; both demos.

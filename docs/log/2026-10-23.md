## Python SDK (`feat/python-sdk`)

- New package `onbehalf` in `sdk/python` (hatchling, Python 3.10+, runtime dependency `httpx` only; `verify` extra adds `cryptography`). The wire format was taken from the server routes and the Rust CLI, not guessed: `POST /token` with the JSON body and `authorization_details` the CLI sends, `POST /token/renew`, `POST /mcp/{server}` with `Accept: application/json, text/event-stream`, `POST /access/v1/evaluation` with an empty `subject.id`, and the `/admin/*` routes.
- `Client` and `AsyncClient`: `exchange` (hop n to n+1, or hop 0 when `client_id` and `client_secret` are given), `renew`, `call_tool`, `list_tools`, `initialize`, `authzen_evaluate`, `inspect(verify=True)`. A `-32003` answer raises `Denied(reason, decision_id)`; the decision id falls back to the `X-Onbehalf-Decision-Id` header. 401 is `Unauthorized`, other JSON-RPC errors are `RpcError`, other non-2xx answers are `ApiError(status, error, detail)`. SSE bodies are parsed per event, so multi-line `data:` works. Request building and response parsing live in one I/O-free module shared by the sync and async classes.
- `AdminClient` and `AsyncAdminClient`: `revoke_lease`, `lease_status`, `audit`, `audit_tail` (checkpoint then pages, as the CLI does), `audit_verify`, `policy_reload`, `mint_root_dev`.
- `Capability("github", "read_file", repo=Prefix("alice/public-"))` with `Equals`, `OneOf`, `Prefix`; serialization is the Rust `Capability` serde shape (`{"op": "prefix", "value": ...}`, `constraints` omitted when empty).
- Token decoding is local and says so: `Token.verified` is false unless `inspect(verify=True)` passed. Verification checks `alg`, the Ed25519 signature against the JWKS, `typ`, `exp`, pinned `iss`/`aud`, and that `sub` and `act` agree with `chain`. It does not check `ou_sig` (the server does on every request).
- Tests: 66 unit tests on `httpx.MockTransport` (every method, sync and async), 4 integration tests behind `ONBEHALF_INTEGRATION=1` that build and start the real server and `fake_mcp`, and replay the GitHub leak scenario through the SDK (dev mint, exchange, allowed call, policy deny, capability deny, widening refused, revoke cascade, `lease_revoked`, audit chain verified and decision ids found in the log), plus both example scripts. `ruff` and `mypy --strict` clean.
- Examples: `examples/python-agent/agent.py` (planner delegates a prefix-constrained `read_file` to a coder, the coder meets an injected instruction, the planner revokes) and `mcp_client_example.py` (official `mcp` client through the proxy; works with `mcp` 2.3.0, the 1.x fallback is untested).
- Separate workflow `.github/workflows/sdk-python.yml` (lint, types, unit tests on 3.10, 3.12, 3.13; integration job with cargo), because `ci.yml` is being edited elsewhere. It has not run on GitHub yet.
- Found along the way: with one `CARGO_TARGET_DIR` shared by several checkouts, `debug/onbehalf-server` is overwritten by whichever checkout built last, so a test that runs "the binary cargo just built" can silently run another branch's server. The integration test copies the binary it starts and `ONBEHALF_BIN_DIR` pins it. Also: the `feat/ops-hardening` work adds a `kid` to token headers; the SDK matches it against the JWKS `kid` like the CLI does, so the two must use the same value.
- Not done: PyPI release, a token-refresh helper that renews and re-exchanges on a timer, streaming (long-lived SSE, server-initiated requests) in `call_tool`, a hop-0 test against a live IdP, a run on Python 3.10 (only 3.13 was available here).

## TypeScript SDK (`feat/typescript-sdk`)

- New package `@onbehalf/sdk` in `sdk/typescript`: tsup builds ESM, CJS and `.d.ts`; strict TypeScript; Node 20+; no runtime dependencies. Same API and wire handling as the Python SDK (exchange body with `authorization_details`, `/mcp/{server}` JSON-RPC with `Accept: application/json, text/event-stream`, SSE and JSON response parsing, `-32003` to `DeniedError`, `-32001` or 401 to `UnauthorizedError`, other JSON-RPC errors to `RpcError`, other statuses to `ApiError`), camelCase names, `OnbehalfClient` and `AdminClient`.
- Local verification uses WebCrypto `Ed25519` (`crypto.subtle`), no library. Same checks as Python (`alg`, signature with `kid` selection, `typ`, `exp`, pinned `iss`/`aud`, `sub` and `act` against the chain). `Token.jwt` is a non-enumerable property so logging a token does not print it.

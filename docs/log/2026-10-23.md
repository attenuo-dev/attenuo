## Python SDK (`feat/python-sdk`)

- New package `onbehalf` in `sdk/python` (hatchling, Python 3.10+, runtime dependency `httpx` only; `verify` extra adds `cryptography`). The wire format was taken from the server routes and the Rust CLI, not guessed: `POST /token` with the JSON body and `authorization_details` the CLI sends, `POST /token/renew`, `POST /mcp/{server}` with `Accept: application/json, text/event-stream`, `POST /access/v1/evaluation` with an empty `subject.id`, and the `/admin/*` routes.
- `Client` and `AsyncClient`: `exchange` (hop n to n+1, or hop 0 when `client_id` and `client_secret` are given), `renew`, `call_tool`, `list_tools`, `initialize`, `authzen_evaluate`, `inspect(verify=True)`. A `-32003` answer raises `Denied(reason, decision_id)`; the decision id falls back to the `X-Onbehalf-Decision-Id` header. 401 is `Unauthorized`, other JSON-RPC errors are `RpcError`, other non-2xx answers are `ApiError(status, error, detail)`. SSE bodies are parsed per event, so multi-line `data:` works. Request building and response parsing live in one I/O-free module shared by the sync and async classes.
- `AdminClient` and `AsyncAdminClient`: `revoke_lease`, `lease_status`, `audit`, `audit_tail` (checkpoint then pages, as the CLI does), `audit_verify`, `policy_reload`, `mint_root_dev`.
- `Capability("github", "read_file", repo=Prefix("alice/public-"))` with `Equals`, `OneOf`, `Prefix`; serialization is the Rust `Capability` serde shape (`{"op": "prefix", "value": ...}`, `constraints` omitted when empty).
- Token decoding is local and says so: `Token.verified` is false unless `inspect(verify=True)` passed. Verification checks `alg`, the Ed25519 signature against the JWKS, `typ`, `exp`, pinned `iss`/`aud`, and that `sub` and `act` agree with `chain`. It does not check `ou_sig` (the server does on every request).

## Proxy list filtering (`feat/proxy-list-filtering`)

- `resources/list`, `resources/templates/list` and `prompts/list` results are filtered like `tools/list`, using the same names as the request mapping: `resources/read` with the `uri` constraint, `prompts/get` with the `name` constraint, templates by tool and server only. `nextCursor` passes through, so a filtered page may be empty with a cursor (the pagination spec allows it).
- Found while doing it: `tools/list` over SSE was passed through unfiltered (SR-23, known and logged as a warning). New `sse` module parses event streams incrementally (LF/CRLF/CR, multi-line data, events split across reads) and filters each event, single message or batch. Fail closed: wrong content type, unparseable JSON, oversized or non-UTF-8 events give 502 / a broken stream; an unterminated final event is dropped.
- A message is a response only when it has no `method` and its id matches a pending list request, so a notification or server request carrying a `result` is never filtered or trusted as one. Tests cover smuggling in single, batch, JSON and SSE.
- `tests/mcp_conformance.rs` walks the method surface table-style; `FakeMcpServer` learned lists, pagination and an event-per-response SSE mode. Spec checked: Streamable HTTP 2025-06-18 removed JSON-RPC batching (the proxy still accepts it for 2025-03-26 clients), and allows a response on a `GET` stream only when resuming.
- Not done: list responses replayed on a resumed `GET` stream are not filtered; no Cedar-aware filtering; `resources/unsubscribe` is still decided as an unknown method.

- SQLite audit and lease I/O now runs on the blocking pool (`AppState::blocking`; `ServerAuthorizer` wraps `Pipeline`). ## SR-27 and SR-28 (`fix/sr27-sr28-streams`)

- SR-27: the proxy now takes exactly one `Mcp-Session-Id`, visible ASCII only (`0x21`-`0x7E`), on `POST`, `GET` and `DELETE`, and answers 400 (`-32600`) otherwise. The header is no longer in the forwarded-header list; the proxy inserts the one value its session gate checked. Upstream responses with two session ids, or an invalid one, lose the header and bind nothing. The ignored test passes; new tests cover `GET`/`DELETE` and the response side.
- SR-28: new `proxy::guard` wraps every streamed response (the `GET` listen stream and streamed `POST` bodies) and re-checks the chain's hop expiry and `Authorizer::check_active` on an interval, `[proxy] stream_recheck_seconds` (default 2, `ProxyConfig::stream_recheck`). On failure an SSE stream gets a last `message` event (JSON-RPC `-32001`, `id: null`, `data.reason` `lease_revoked`, `token_expired`, ...) and ends; other bodies end with a transport error. A biased `select!` lets a due tick win over a ready chunk, so a busy stream is checked on time.
- To append that event safely, SSE passthrough bodies are now framed event by event (`sse::frame_stream`, bytes unchanged), which also drops an unterminated last event and caps events at 16 MiB, like the list filter already did.
- Tests run the interval at 100 ms: revoked stream ends within a few intervals with `lease_revoked`, expired token ends with `token_expired`, an untouched stream keeps flowing, a revoked SSE `tools/call` response ends. Report statuses (pass 1 SR-09/SR-11, pass 3 SR-27/SR-28), `docs/design/server.md`, config reference, example config and changelog updated.

## Actor authentication (`feat/actor-token`)

- An exchange (hop n+1) can now authenticate its `actor` with an RFC 8693 `actor_token` instead of an `[[agents]]` secret. New `[[actor_trust]]`: a SPIFFE trust domain whose JWT-SVID keys come from the SPIRE bundle endpoint URL (given explicitly, no discovery), or any issuer with a `jwks_url`. Keys go through the existing `[[idps]]` JWKS cache; its parser now keeps `use = "jwt-svid"` keys (one additive line in `idp/jwks.rs`). New module `crates/onbehalf-server/src/actor.rs`.
- `[token] actor_auth = "secret" | "actor_token" | "either"`, default `either`, so existing configs are unchanged. `require_actor_auth = true` still means one method is mandatory; when both are sent, both are checked. `actor_token` mode refuses to start without an `[[actor_trust]]` entry.
- Single use: the actor token's (entry, `jti`), or the SHA-256 of its signing input, goes through the replay cache; a refused exchange does not consume it. The child's expiry is capped at the actor token's `exp` (`IssueOptions::not_after` in `onbehalf-token`).
- `may_act` (RFC 8693 §4.4) on issued tokens, from the request or `[[root_grants]] may_act` (a ceiling), enforced in `Issuer::exchange_with` as `actor_not_permitted`. Not inherited by children. Absent keeps the old behaviour.
- CLI `--actor-token` / `--actor-token-file` / `--may-act`; Python `actor_token=` and `may_act=`; TypeScript `{ actorToken, mayAct }`. ADR-0007, RFC §3.1/§4, config, HTTP and CLI references, identity-providers guide (SPIRE section, untested against a live SPIRE), SR-10 status.

## End-to-end benchmark (`feat/e2e-bench`)

- New crate `onbehalf-bench` (tokio, reqwest, hdrhistogram, clap, serde) and `scripts/bench-e2e.sh`. The harness copies and starts the release `onbehalf-server` and `fake_mcp`, mints a root token with the dev mint, exchanges down to 1 and 3 hops, and drives `tools/call` with closed-loop clients through the proxy and straight at the upstream. Scenarios: allow, deny by policy, deny by capability; 1, 8, 32 clients; audit in memory and in a SQLite file. It fails if any answer is not what the scenario expects or if `GET /admin/audit/verify` is not ok with at least one entry per proxied call. Output is a table and JSON.
- First real run committed in `docs/design/bench/2026-10-23-vm.{json,md}` (4 vCPU shared dev container, other builds running, so noisy). Headline: with the audit log in memory a one-hop allow call costs about 0.7 ms more than calling the upstream directly at p50 (1.2 ms at p99), three hops about 1.0 ms; throughput about 4,500 calls per second at one hop and 2,200 at three, against 48,000 direct. With a SQLite file the proxy managed 300 to 600 calls per second: the audit append is a synced commit per decision.
- Docs: `performance.md` has the method, headline numbers and caveats; the FAQ latency answer quotes them instead of "unmeasured"; RQ2 in the evaluation plan points at the harness and lists what is still missing (open-loop load, repeated runs, intervals). Findings are on the board; no server, proxy, token or policy source was touched.
- A smoke test (`crates/onbehalf-bench/tests/smoke.rs`) runs a one-second scenario in `cargo test`. No CI job for the full matrix: it needs a release build and minutes of load, and shared runners would make the numbers incomparable.
- Closed-loop load understates tail latency under overload (coordinated omission); the open-loop version is still to do.

## Audit write path and per-call cost (`perf/audit-write-path`)

- WAL plus `synchronous=NORMAL` for the audit and lease stores, `[audit] durability = "normal" | "full"` (default normal), busy timeout, statement cache. Revocations always commit with `synchronous=FULL`. At `normal` a power failure can lose the newest decisions but never tear one; the chain verifies with an earlier head. Documented in the config reference, deploy guide and example config.
- Group commit: one writer thread behind an mpsc channel, commits everything queued (up to 256) in one transaction, per-append replies; a failed batch is retried one record at a time so a refused record alone is denied with `audit_error`. No linger window: records arriving during a commit form the next batch, and a 1 ms wait would add 1 ms to every lone call without enlarging batches under closed-loop load. New tests: 8 writers on a file log with checkpoints every 7 at both durabilities while another thread verifies and requests timer checkpoints; a trigger-refused record inside concurrent batches.
- Per-call waste found with a new criterion bench (`onbehalf-server/benches/decide.rs`) and temporary timers in the commit: token verification on every call (about 100 us, now a cache keyed by token hash, expiry rechecked), the append decoding the whole head row (now `seq, entry_hash`), double serialization of each record, a record clone, one lease query per hop (now one `IN (...)` query; faster for files, slower in memory, a few us either way). Cedar stays the biggest stage and grows about 18 us per hop; that and a token-crate idea are on the board.

### 14:05 UTC: the WAL backstop, second attempt

`fix/wal-writer-backstop` (#19) set `wal_autocheckpoint` on the writer as a backstop and CI showed it does nothing under load: the bounded-WAL test reached 335 MB on the Linux runner. Results in `docs/design/bench/2026-10-23-vm-wal-backstop.md`, summary in performance.md.

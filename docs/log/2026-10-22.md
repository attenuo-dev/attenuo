# 2026-10-22

## Project started

- Picked the problem: a self-hosted, IdP-neutral authorization and enforcement plane for AI agents, sitting between agent clients and MCP servers. Four guarantees: verified originating user per hop, monotonic attenuation, argument-aware per-call policy, hash-chained audit with lease-based revocation.
- Repository skeleton landed: Cargo workspace, CI, Apache 2.0, docs vault.
- Wrote the first docs set: [RFC-0001](../spec/rfc-0001-onbehalf.md), [threat model](../spec/threat-model.md), ADRs [0001](../decisions/0001-separate-enforcement-layer.md) (separate enforcement layer), [0002](../decisions/0002-cedar-for-policy.md) (Cedar), [0003](../decisions/0003-apache-2-license.md) (licence), [0004](../decisions/0004-rust-workspace-layout.md) (crate layout); research notes on [standards](../research/standards.md), [incidents](../research/incidents-2025-2026.md), [related work](../research/related-work.md); the [board](../tasks/board.md) and [milestones](../tasks/milestones.md).
- Decisions made today and not to be revisited soon: enforcement point is the proxy/PDP, not a sandbox; Cedar is the only policy language; attenuation is a code predicate in `onbehalf-core`, not a policy.
- Next: `onbehalf-core` capability types and the `⊑` proptest suite.

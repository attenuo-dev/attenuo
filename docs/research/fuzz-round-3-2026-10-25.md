# Fuzzing, round 3 (2026-10-25)

- Status: done on `test/fuzz-round-3`, from main @ 5812210
- Crate: `fuzz/` (cargo-fuzz, libFuzzer), as in the [first campaign](../design/fuzzing.md) and [round 2](fuzzing-2026-10-24-round2.md)
- Related: [security review pass 7](security-review-2026-10-25-pass7.md)

Security pass 7 (#124) changed how the proxy reads upstream SSE: a byte order mark that opens the stream is dropped (SR-77), a non-UTF-8 event is refused, a lone surrogate escape is read as U+FFFD (SR-78), an event whose data does not parse is dropped (SR-80), and the stream-end guard drops an event that may hold the code `-32001` but does not parse (SR-79). An upstream controls every byte of that input. The existing `proxy_sse` target covers the framer and rewriter through their public API; this round adds two targets that reach the crate-private helpers too.

Those helpers are `pub(crate)`. They are reached through `attenuo_proxy::fuzzing`, a `#[doc(hidden)]` module of thin wrappers that exists only with the crate's `fuzzing` feature, which only `fuzz/Cargo.toml` turns on. This is the first exception to the "public APIs only" rule of the earlier campaigns.

## Targets

| Target | What it calls | Invariant beyond "no panic" |
| --- | --- | --- |
| `sse_framer_rewriter` | `strip_leading_bom`, `SseFramer::push`, `SseRewriter::push`, `rewrite_event`, `has_data`, `event_json`, `split_events`, `may_hold_stream_end_code` and `disown_events`, on raw bytes or generated events (BOM, `\n` / `\r\n` / `\r` line ends, `data` with and without `:` and space, data split over two lines, `-32001` in 11 spellings, lone and paired surrogate escapes) cut at arbitrary points, with limits of 8 bytes to unlimited | `strip_leading_bom` leaves the same bytes whatever the chunking and decides only once it can; the framer emits the input less a leading BOM, as whole UTF-8 events, the same for any chunking; the rewriter's output and errors do not depend on the chunking, and its output is at most 5 times its input plus 8 bytes; `rewrite_event` relays a data-less event byte for byte, drops one whose data does not parse, and calls `f` exactly when the data parses; `may_hold_stream_end_code` is true for every event in which some `-` starts a JSON number equal to -32001 and for every event a client would parse as a stream end; after `disown_events` (on the framed output and on the raw stream) no whole event parses to the stream-end shape, and a second pass changes nothing |
| `sse_parse_data` | `parse_data` and `replace_lone_surrogates` on arbitrary UTF-8 text and on JSON strings built from escapes (lone high and low surrogates, pairs, upper-case hex, escaped backslashes before `ud800`) | when `serde_json` accepts the text, `parse_data` returns the same value and the replacement leaves the text alone; text without `\u` is never changed; the replacement keeps the length and is idempotent; a result round-trips through `serde_json`; a string literal of escapes always parses |

## Run

Same container as earlier rounds (4 vCPU, shared with a clippy and test build during the run), no seed corpus, both targets at once. The run had to fit a fixed push deadline, so each target ran 300 s, not the 600 s of earlier rounds. Counts are libFuzzer's final figures.

| Target | Run (s) | Executions | Edges | Corpus at the end |
| --- | ---: | ---: | ---: | --- |
| `sse_framer_rewriter` | 300 | 313,533 | 2,784 | 1,873 inputs, 86 KB |
| `sse_parse_data` | 300 | 4,427,579 | 2,693 | 2,801 inputs, 241 KB |

A first `sse_framer_rewriter` run stopped after about 12,000 executions on a fault in the target, not in the proxy: its check that framed output ends with an empty line did not list `\r\r\n` (a `\r`-terminated line followed by a `\r\n` empty line, input `event: message\r\nid: 7\r\ndata:\r\r\n`), which `find_event_end` rightly treats as an event end. The check was corrected and the target ran again from the corpus it had built. Corpora were not kept, as in earlier rounds (`fuzz/.gitignore`).

## Findings

None in the proxy. Both targets ran 300 s without a panic or a property violation after the target fix above, so no regression test was added. `sse_framer_rewriter` is slow (about 1,000 executions a second) because its `-32001` oracle parses every prefix of every number run after a `-`; a longer run would buy more than the 300 s the deadline allowed.

The existing `proxy_jsonrpc` target no longer compiled on main (its `ProxyConfig` lacked the `record_window` fields added since round 2); it now passes the defaults, so `cargo +nightly fuzz build` builds all 19 targets again.

## Not covered

- The streaming wrappers (`rewrite_stream`, `frame_stream`) and the guard's stream-level state; `proxy_sse` and the proxy's integration tests cover those.
- Clients other than `serde_json`: the targets check the proxy's reading, and that its replacement of lone surrogates matches what `JSON.parse` prints is argued in SR-78, not fuzzed against a JavaScript parser.

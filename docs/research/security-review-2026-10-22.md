## Scope and method

A source review of every crate with the threat model's attacker in mind (A1 to A7: a compromised agent or sub-agent, an untrusted MCP server, a party replaying tokens). The question for each finding is whether it breaks one of the four guaranteed properties: P1 (verified originating user per hop), P2 (monotonic attenuation), P3 (argument-aware per-call authorization, deny by default) or P4 (tamper-evident audit and in-flight revocation). Suspected issues were confirmed with a test before they were reported. Every finding fixed on this branch has a regression test that fails without the fix.

Order of review: `onbehalf-token`, `onbehalf-core`, `onbehalf-policy`, `onbehalf-audit`, `onbehalf-proxy` and `onbehalf-server`, then dependency checks.

Out of scope: the concurrent branch `feat/leases-and-coverage`, which adds enforcement for `resources/read`, `prompts/get` and unknown methods and adds lease renewal. Gaps in that area are reported below (SR-09) but not fixed here.

"Partly fixed" is SR-13 (`/` in server names rejected; actions are still not server-scoped), SR-24 (IdP credentials and exchanges are single-use; tokens are still bearer tokens) and SR-25 (unknown names are denied through SR-12; no normalization).

The three biggest open risks at the time of pass 1 (SR-08 and SR-10 are now fixed):

1. **SR-08.** The AuthZEN endpoint accepts an unsigned chain from any caller. Lease ids are printed in every token, so anyone who has seen a token can forge a chain for any user with any attributes and capabilities, get `allow` decisions for it, and write audit records in that user's name.
2. **SR-09.** Revocation is only checked on `tools/call`. A revoked token can still list tools, hold the server-to-client SSE stream open, end sessions, and send every other MCP method.
3. **SR-10.** `actor` is whatever the caller says. Any token holder can mint a child that names any agent, which spoofs `principal` in Cedar and the agent recorded in the audit log.

## Checked and found sound

- **JWT handling.** `Validation::new(EdDSA)` pins the algorithm, so `none` and algorithm confusion are rejected by `jsonwebtoken`. `kid` is ignored (single key). The header and claim `typ` must both equal `onbehalf+jwt`. `iss` and `aud` are compared exactly. `exp <= now` is rejected with no leeway, the boundary matches `validate_at`, and `exp` must equal the last hop's expiry. `sub` and `act` must be rebuilt exactly from the chain, so `act` nesting cannot disagree with `chain`.
- **Exchange.** An expired parent fails verification. A revoked parent is refused by the server's lease check before minting (not by `Issuer::exchange` itself, which is documented as such). TTL is clamped to the parent's expiry. The child's lease is registered under the parent's, so revocation cascades.
- **Attenuation.** `pattern_covers` is sound for `*`, `p*` against `q*`, exact names, and `*` in the middle of a name (which is treated as a literal). The implication table matches RFC §3, including the vacuous empty `one_of`. `permits` requires every constrained argument to be present. Covering only by a union of parent capabilities is rejected.
- **Cedar input.** Keys starting with `__` are rejected at every depth, so no entity or extension can be forged from `context.input`. JSON nesting is bounded by `serde_json`'s recursion limit (128). Entity ids are opaque strings, so quotes and dots cannot inject. Evaluation errors and translation errors deny. The capability stage always runs before Cedar, in the one `authorize` path used by both the proxy and AuthZEN. Policy reload takes the write lock and swaps atomically, and an invalid set keeps the previous one in force.
- **Audit chain.** The entry hash is SHA-256 over the JSON array `(seq, prev_hash, record)`, so field boundaries are unambiguous. On read, rows must round-trip to their canonical encoding and the indexed columns must match `record_json`. Lease times are compared as parsed `OffsetDateTime`, not as text. Unknown leases fail closed. The revoke cascade is a recursive CTE with `UNION`, so a cycle terminates.
- **Proxy surface.** `Authorization` is not forwarded upstream. `/mcp/{server}` only resolves configured upstreams to fixed URLs, so there is no path traversal. Batches are re-encoded without the denied members. The admin bearer is compared in constant time (only the length leaks). With no admin token configured, admin routes fail closed with 403. The default bind address is `127.0.0.1`.

The two open Medium findings are both in the proxy, and both weaken a pass 2 or pass 1 guarantee:

1. **SR-27.** The session gate checks only the first `Mcp-Session-Id` header (none at all if that value is not visible ASCII), but the proxy forwards every value. SR-11's binding can be bypassed against any upstream that reads a later header.
2. **SR-28.** A `GET` listen stream, or a `tools/call` answered over SSE, is lease-checked once, when it opens. Revocation and token expiry do not end it, so in-flight revocation (P4) does not reach long-lived streams.

Fixed here: an ID token without `jti` signed with ECDSA could be redeemed twice by re-encoding its signature (SR-29), and the release workflow ran third-party actions from mutable tags with image-push, signing and release permissions (SR-30).

Pass 2 fixes were re-checked; their status column in the [pass 1 report](security-review-2026-10-22.md) is updated. SR-09 is now verified fixed (apart from SR-28), SR-11 is incomplete (SR-27), SR-24's replay cache had a bypass (SR-29, fixed), and SR-26 is fixed.

## Checked and found sound

- **Replay cache.** `use_once` checks and inserts under one lock, so two concurrent redemptions of one credential cannot both pass. It is called after issuance and before the lease is registered, so a request that loses the race mints a token whose lease is never registered (unusable: `lease_unknown`) and never returns it. Entries live until the credential's `exp` plus skew, the last instant it could be accepted. A full cache refuses issuance with 503 instead of forgetting entries. Exchange keys use the parent's `jti` claim, not its encoding, so EdDSA tokens (not malleable in `ring`, which rejects `s >= L`) and the parent's re-encoding are irrelevant.
- **Lease TOCTOU.** An exchange that races a revocation of its parent registers the child after the cascade, so the child's own row stays unrevoked; every use of the child still fails, because `check_all` checks every lease of the chain, including the revoked parent. Renewal checks all ancestors and the store refuses to renew a revoked lease inside an immediate transaction; a renewal whose audit append fails restores the previous expiry. Revocation in the SQLite store is one recursive `UPDATE` in an immediate transaction.
- **AuthZEN (SR-08).** With a bearer, a body chain must equal the token's chain, and `subject.id` must be the chain's current agent. Without one, the PEP must authenticate and every hop's prefix digest must equal the write-once binding recorded at issuance, checked before any audit record is written. A PEP holding a credential can evaluate any chain it has seen in a token (attacker e), but nothing it has not seen, and not after the leases are revoked; that is the documented trust in a PEP. Because `preserve_order` is on (SR-20), a PEP that reorders keys inside attribute values gets `chain_not_issued`: fail closed.
- **Actor authentication (SR-10).** The authenticated client id must equal `actor`; `duplicate_actor` is checked against the whole parent chain; Basic and body credentials cannot be mixed; unknown ids are compared against a dummy hash. A compromised sub-agent (attacker b) can only receive delegations in its own name. It can still redeem any parent token it gets hold of for itself (no `may_act` yet), which is on the board.
- **Key rotation.** A token with a `kid` is checked only against the key with that `kid`; an unknown `kid` is refused; tokens without one are tried against every trusted key. The algorithm is pinned to EdDSA for every key, header and claim `typ` must both be `onbehalf+jwt`, so neither `alg` nor `typ` confusion is possible. Retired keys verify but never sign, and `ou_sig` must verify under a trusted key. Previous keys may be given as public PEMs, so old private keys need not stay on disk.
- **IdP intake.** `alg` must be in the issuer's `allowed_algs`, symmetric algorithms are refused in config, `oct` JWKs are dropped, and a JWK's own `alg` must match the token's. `iss` is re-checked after signature verification (the pre-signature peek only selects the issuer). ID tokens with a `+jwt` `typ` (ID-JAGs, access tokens) are refused, and ID-JAGs must carry their `typ` and our issuer as audience. JWKS fetches are size- and count-bounded, a refetch for an unknown `kid` is rate-limited, and a failed refresh drops the old keys.
- **Session binding (SR-11), apart from SR-27 (since fixed).** The owner is (subject, issuer, root lease), so another run of the same user is someone else. An upstream cannot rebind a live session to another principal; an unknown session id gets 404 and is never forwarded; logs and audit records carry a hash prefix of the id. Sub-agents of the same run share the session by design: they can attach to the parent's listen stream, but every call is still authorized against the sub-agent's own capabilities.
- **Admin surface (SR-15).** Off loopback, the server refuses to start without a token of at least 32 bytes that is not a published placeholder, including when no token is set; the compose file requires `ONBEHALF_ADMIN_TOKEN` and publishes on `127.0.0.1` only. Revocations, reloads (including failed ones) and dev root mints are audited; a revocation stands even if its audit append fails.
- **Metrics.** Label values come from route templates, fixed reason codes and status codes, so request data cannot grow cardinality; label values are escaped. The endpoint is only on its own listener, loopback by default.
- **Graceful shutdown.** Every handler that issues a token or a decision does its lease registration and audit append synchronously in one poll, so the drain timeout's abort cannot leave a token issued without a record. An aborted proxied call can leave an `allow` record for a call that was never forwarded, which errs on the side of over-recording.
- **Unknown tools and the harness.** The catalog stage runs before Cedar in `PolicyEngine::authorize`, which the proxy, AuthZEN and `onbehalf policy test` all call, and the harness picks up `[policy] unknown_tools` and `user_attributes` from a server config, so tests and production cannot silently disagree on uncatalogued tools.
- **CLI and SDK token verification.** `onbehalf token inspect --verify`, `verify_token` (Python) and `verifyToken` (TypeScript) fetch the JWKS from the configured server (never from the token's `iss`), pin `alg` to EdDSA, select the key by `kid`, verify Ed25519 over the exact signing input, and check claim `typ`, `exp`, and `sub`/`act` against the chain. They do not check the header `typ` or `ou_sig` (documented; the server checks both on every request), and `iss`/`aud` are only pinned when the caller passes them; since the keys come from the same server, that is acceptable. Python and TypeScript SSE parsing only accepts `data:` lines and JSON-decodes each event, and the proxy's own SSE prelude is serialized JSON, which contains no raw newlines, so neither side can inject events. Tokens are kept out of `repr` / enumeration, and `httpx` does not follow redirects by default.
- **Workflows.** Every workflow defaults to `contents: read`, there is no `pull_request_target`, and `${{ }}` expressions in `run:` blocks only expand values the attacker cannot set (matrix values, step outputs); the tag name reaches shell through `GITHUB_REF_NAME`. mdBook is installed from a pinned version checked against a SHA-256. The `audit` job's `checks: write` is the only extra permission on PR runs, and fork PRs get a read-only token.
